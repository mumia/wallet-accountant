# 07: Grafana stack and single sign-on for the admin tools

**What to build:** the Grafana stack as a platform component, opt-in locally through `make local-up-observability`, with the app's telemetry visible. Grafana and Headlamp sign in through Zitadel, and the break-glass logins still work. Spec: `../spec.md` ("Platform", user stories 5 and 16); ADR-0016, ADR-0022.

**Blocked by:** 04

**Status:** resolved

- [ ] Prometheus (with its OTLP receiver), Loki, Tempo and Grafana HelmReleases in `platform/observability`, a Flux Kustomization that `clusters/local` includes only when the observability flag is set; `clusters/prod` always includes it
- [ ] Data sources provisioned like `deploy/selfhosted/grafana/provisioning` today, including trace-to-logs links
- [ ] The app chart's collector exports to the stack when it's present and discards otherwise
- [ ] A platform setup Job (same mechanism as the app's) creates Zitadel apps for Grafana and Headlamp
- [ ] Grafana: generic OAuth through Zitadel, plus the local admin kept, its password in a Secret
- [ ] Headlamp: OIDC through Zitadel, plus token login kept
- [ ] A runbook page in the env repo: "Zitadel is down", using kubectl, the Grafana admin and a Headlamp token

## Comments

**Implementer (2026-11-20).** Env repo branch `ticket-07` (not pushed). `deploy/local/check.sh` has one check (or more) per criterion. On 2026-11-20, both runs below passed from a freshly rebuilt cluster: `make local-down && make local-up-observability && make local-deploy && OBSERVABILITY=true make local-check` (72 checks), and `make local-down && make local-up && make local-deploy && make local-check` (52 checks). Turning the stack off on a running cluster (`make local-up` after `local-up-observability`) pruned the `monitoring` namespace and switched the app's collector back to `nop`.

- **Opt-in switch.** `clusters/local/observability` is its own Flux Kustomization (`clusters/local/flux-system/observability.yaml`), outside the `cluster` entry point. `make local-up-observability` applies it, and `make local-up` deletes it, which prunes the stack. It also carries the ConfigMap `flux-system/observability` (`OBSERVABILITY: "true"`). The app's Flux Kustomization reads that ConfigMap with `substituteFrom` (`optional: true`) and sets the chart's new `collector.grafanaStack.enabled` to `${OBSERVABILITY:=false}`. Production gets `clusters/prod/observability.yaml` (the stack, `grafana-sso`, and the flag set to true) and `clusters/prod/headlamp-sso.yaml`, and ticket 11 adds both to its kustomization.
- **The stack.** `platform/observability` holds the Prometheus (community chart, server only, `web.enable-otlp-receiver`), Loki (Monolithic, filesystem), Tempo (single binary) and Grafana HelmReleases. The latter three come from the `grafana-community` chart repository. Data sources are a copy of `deploy/selfhosted/grafana/provisioning`, trace-to-logs links included, kept out of Flux substitution. Locally, Prometheus's Kubernetes scrape jobs are off to save memory, so it holds only what arrives over OTLP.
- **Chart.** `collector.grafanaStack.enabled` (default false) replaces the pipelines with one `otlphttp` exporter per signal. The endpoints are in `collector.grafanaStack.endpoints.*` and default to `*.monitoring`. There is a chart test, and the schema covers it. Live, the check sends a trace, a log and a metric through the chart's collector, and also finds the app's own traces, logs and metrics in Tempo, Loki and Prometheus.
- **Platform setup Job.** `platform/zitadel-oidc-client` uses the same mechanism as the app's setup Job: curl with the `platform-setup` PAT, run once per tool by its own Flux Kustomization (`headlamp-sso`, `grafana-sso`). It creates the Zitadel project `platform` with role assertion and "authorization required", the role `admin` (granted to `PLATFORM_ADMINS`, which locally is the first-instance admin), and a confidential web app. It writes `<tool>-oidc` (client ID and secret, issuer, enabled) and restarts the tool. The tools read that Secret through optional env vars, so they start with only break-glass sign-in until the Job has run.
- **Headlamp.** OIDC through Zitadel. The k3s API server accepts Zitadel ID tokens through an AuthenticationConfiguration (`clusters/local/apiserver/authentication.yaml`, mounted by k3d with the mkcert CA and a host alias of `auth.localhost` to the fixed ClusterIP `10.43.0.100` of `localhost-ingress`). The role maps to the group `zitadel:admin`, which is bound to cluster-admin. The token login is unchanged. **Changing `clusters/local/k3d.yaml` needs a new cluster.** In production, the k3s config (ticket 10/11 cloud-init) has to pass the same `authentication-config`, with the prod issuer.
- **Grafana.** Generic OAuth through Zitadel. `role_attribute_strict`: only users with the project role `admin` sign in, and they become Admin. The local admin is kept, with its password in `monitoring/grafana-admin` (plain throwaway locally, SOPS in prod).
- **Runbook.** `runbooks/zitadel-is-down.md` in the env repo.
- **Fixes found on the way.** (1) The Makefile already had a Compose variable called `OBSERVABILITY`, which silently overrode `OBSERVABILITY=true make local-check`. It is now `COMPOSE_OBSERVABILITY`. (2) Under load, `kubectl run -i` sometimes lost the end of the bootstrap pod's output, so local-check saw no code. Re-issuing replaces the code, so the check now tries up to three times.
- **Watch out.** During my first attempt, Docker Desktop's VM restarted on its own (about 12:28, while the stack was starting; memory was not under pressure afterwards). The registry came back with a new IP, so the cluster could no longer pull its artifact, and only `make local-down` and a fresh rebuild recovered it. The previous implementer's 09:06 run probably died the same way ("http2: client connection lost"). If a run hangs on "Source artifact not found", check `docker ps` uptimes.
- **Not done.** Production is untested: `clusters/prod` has no `kustomization.yaml` yet (ticket 11). The Flux source name `flux-system` and the `sops-age` Secret in the prod files are assumptions. I did not try the Grafana and Headlamp sign-in in a real browser; the check signs in to Zitadel's v1 login UI with curl and follows the redirects back to each tool.
