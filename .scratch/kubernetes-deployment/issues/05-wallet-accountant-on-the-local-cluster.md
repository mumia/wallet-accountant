# 05: Wallet Accountant on the local cluster

**What to build:** `make local-up && make local-deploy` gives a working app at `https://wallet.localhost/api`. The developer can bootstrap and redeem an Invitation, call the API from Bruno, and switch to debug mode (`make run` on the host against the in-cluster dependencies). Spec: `../spec.md` (user stories 10, 13–15); ADR-0019.

**Blocked by:** 02, 04

**Status:** resolved

- [ ] `apps/wallet-accountant` HelmRelease with `database.mode: external` on `apps-db`, Zitadel setup on, UI off, at `wallet.localhost`
- [ ] `local-deploy` builds the image from this repo's working tree, pushes it to the k3d registry, and sets its tag in the pushed artifact (a unique tag per build, so Flux rolls it out)
- [ ] `make local-bootstrap` and `make local-rebuild` run the one-off pods from ticket 02. The code prints only to the terminal, and the pod is removed
- [ ] Debug mode: `apps-db` on `localhost:5432` and the collector on `localhost:4318`. `make run` defaults point at them, with `WA_OIDC_ISSUER=https://auth.localhost`. Go trusts the mkcert CA through the macOS keychain; verify it
- [ ] `api/bruno/.env` gets the `api-clients` client ID from the setup Job's ConfigMap; the Bruno environment's URLs are `https://wallet.localhost/api` and `https://auth.localhost`
- [ ] Swagger UI at `https://swagger.localhost` in the local cluster only, showing `api/openapi.yaml`
- [ ] README: the new development section

## Comments

**Implementer (2026-11-19).** Env repo branch `ticket-05` (not pushed). Test-first: `deploy/local/check.sh` got one check per criterion, failed on each against a cluster without the app, then passed after `make local-down && make local-up && make local-deploy` from scratch, and again after a second `make local-deploy` (the setup Job's update path).

- **Every URL carries `:18443`**: the app is at `https://wallet.localhost:18443/api`, the issuer is `https://auth.localhost:18443`, Swagger UI is at `https://swagger.localhost:18443`. The criteria's port-less URLs hold only with `LOCAL_HTTPS_PORT=443`.
- **Delivery.** `make local-deploy` = `local-build` + `local-push` + reconcile + wait + `local-bruno-env`. `local-build` builds the image (`docker build`) and packages the chart from this working tree, with tag `local-<UTC stamp>` and chart version `<Chart.yaml version>-local.<stamp>`. It pushes both to `localhost:5050` (pulled in the cluster as `wa-registry:5000/...`) and records them in `bin/local-build.env`. `local-push` now pushes a staged copy (`deploy/local/stage.sh`, in `bin/local-artifact`) of the env repo's working tree, never changing the tree itself. The copy adds this Mac's mkcert CA cert, `api/openapi.yaml`, and, when the recorded image is still in the registry, a generated `clusters/local/build` Component that adds `clusters/local/apps` and the ConfigMap `flux-system/wallet-accountant-build`. As committed, `build` is an empty Component (it needs `resources: []`, because kustomize rejects an empty file), so `make local-up` alone runs no app. After `local-down`/`local-up`, the last build is deployed again.
- **Env repo layout.** `apps/wallet-accountant/release.yaml` holds the production-shaped base: an `OCIRepository` on `ghcr.io/mumia/charts/wallet-accountant` with `ref.tag: ${WALLET_ACCOUNTANT_VERSION}`, plus a HelmRelease with `chartRef` and the values `database.mode: external`, Zitadel setup on and UI off, at `wallet.${DOMAIN}`. The `wallet-accountant` Flux Kustomization (`clusters/local/apps/wallet-accountant.yaml`, `targetNamespace: wallet-accountant`, dependsOn `tenant-wallet-accountant` and `gateway`) is where the local values live. It patches the chart URL to the k3d registry (insecure), sets the image repository and tag, `route.port: 18443`, the issuer with its port, `oidc.zitadelSetup.connectTo` and `trust.caConfigMap: mkcert-ca`. It adds a local Component with the `mkcert-ca` ConfigMap and the collector's debug Service. The namespace is not declared again. Ticket 11 has to substitute `DOMAIN` and `WALLET_ACCOUNTANT_VERSION` in prod.
- **Chart changes.** I added two values. `route.port` (0 = the scheme's default) puts the port into the `web` redirect and post-logout URIs; I chose it over `extraRedirectUris` so that no port-less URI is registered. `oidc.zitadelSetup.connectTo` (`host:port`, curl `--connect-to`) is needed because curl answers every `*.localhost` with 127.0.0.1 itself, so the Job could never reach `https://auth.localhost:18443`. Locally it connects to `localhost-ingress.kube-system.svc.cluster.local:18443`, and TLS is still verified for `auth.localhost`. Both have chart tests and schema rejections.
- **Setup Job against the real Zitadel (v4.19.2).** It worked on the first run with no API fixes. The v2 `ProjectService`/`ApplicationService` paths, the `applicationId` field, the `UpdateApplication` body (verified by changing a redirect URI by hand: 200) and the `PUT /admin/v1/settings/oidc` lifetimes all held. An unchanged update answers 400 `failed_precondition` "No changes (COMMAND-1m88i)", which `unchanged()` matches. The second run logs "is up to date".
- **Operator pods.** `make local-bootstrap` and `make local-rebuild` call `deploy/local/operator-pod.sh`. It renders `operator-pod.yaml` from the installed release's chart, pulled from the k3d registry (Flux installs it as `<version>+<digest>`, so the script strips the suffix), with `helm get values`. It then runs `kubectl run --rm -i --quiet`. The check confirms the code is printed, no pod is left, and the code is in no log in the namespace.
- **Debug mode.** k3d now also publishes `LOCAL_DB_PORT` (5432) and `LOCAL_OTLP_PORT` (4318), and the cluster has to be re-created for that. LoadBalancer Services (k3s servicelb) put them on the node: `databases/apps-db-debug` (selector `cnpg.io/instanceRole: primary`, a Component of the `apps-db` Kustomization) and `wallet-accountant/collector-debug`. The `make run` defaults are now the cluster: the throwaway `wa_*` passwords with `sslmode=require`, `WA_OIDC_ISSUER=https://auth.localhost:18443` and OTLP on `localhost:4318`. **Verified:** the check runs `make run` with `SSL_CERT_FILE`/`SSL_CERT_DIR` unset, and the first Go request to `/api/me` with a real Zitadel JWT got 403 `registration-required` (so the token verified), then 200 after redeeming. That means Go fetched the discovery document and the JWKS over TLS with the mkcert CA trusted through the macOS keychain, and macOS resolves `auth.localhost` to loopback.
- **Real identity in the check.** `local-check` creates (once) a Zitadel machine user `local-check` with JWT access tokens, gets a client-credentials token with scope `urn:zitadel:iam:org:project:id:wallet-accountant:aud`, redeems the fresh bootstrap code (201, or 409 on later runs) and expects `is_instance_administrator` on `/api/me`. Ticket 08's smoke test can reuse this.
- **Bruno.** `api/bruno/environments/local.yml` (the environment `local`) points at the cluster. The collection's default `authUrl` is now `https://auth.localhost:18443`, so the no-environment path (`make run`) signs in to the same Zitadel. `local-deploy` writes `.env` from the ConfigMap. Bruno itself needs the mkcert CA added under Preferences, which is documented. I did not try Bruno's interactive sign-in.
- **Swagger UI.** `clusters/local/swagger` (Flux Kustomization `swagger`, dependsOn `gateway`), `swaggerapi/swagger-ui:v5.34.1` (added to `images.lock`, `RENOVATE_ENV_EXPECT`), the spec from a ConfigMap generated from the staged `openapi.yaml`, read-only as before.
- **Left as is.** The Compose `dev-*` targets still exist (ticket 14 removes them), but `make run`/`migrate` no longer point at them, and Compose's PostgreSQL would clash with the cluster on 5432. Ticket 07 may want the same mkcert CA ConfigMap for Grafana/Headlamp SSO; here it is generated only inside the app's Kustomization.
