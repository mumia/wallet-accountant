# 04: CloudNativePG and Zitadel in the platform

**What to build:** the platform's PostgreSQL and identity provider, running locally. The CNPG operator runs `zitadel-db` and `apps-db`; `apps-db` gets a tenants list. Zitadel runs at `https://auth.localhost` on `zitadel-db`, with an admin login and a machine user whose token app setup Jobs use. Spec: `../spec.md` ("Platform"); ADR-0022, ADR-0023.

**Blocked by:** 03

**Status:** claimed

- [ ] CNPG operator HelmRelease; `zitadel-db` and `apps-db` `Cluster`s, single instance each, with sizes from cluster values
- [ ] `apps-db` tenants list: per tenant, a `Database`, an owner role (managed role) and its password Secret. Wallet Accountant's owner `wa_owner` has `BYPASSRLS` and `CREATEROLE` (ADR-0014)
- [ ] The tenant's connection Secrets are made available in the app's namespace (encrypted copies in prod, plain in local, as decided)
- [ ] Zitadel HelmRelease on `zitadel-db`, external domain `auth.localhost`, TLS ended at the Gateway, self-registration off, the v1 login UI as today
- [ ] The first-instance human admin, plus a machine user with a personal access token stored in a Secret for setup Jobs
- [ ] Zitadel's issuer URL works both from the browser and from a pod (through the ticket 03 CoreDNS rewrite)
- [ ] The Zitadel masterkey comes from a Secret (throwaway locally); add it to the spec's 1Password list for prod

## Comments

**Implementer (2026-11-19).** Env repo branch `ticket-04` (not pushed). Verified with `make local-down && make local-up` from scratch, followed by `make local-check`. The check in `deploy/local/check.sh` was extended first: it failed on each criterion, then passed against the live cluster.

- **Ports (user request).** `LOCAL_HTTP_PORT` / `LOCAL_HTTPS_PORT` now default to 18080 / 18443, so the kind cluster `keystone` keeps 80 / 443. Every browser URL carries `:18443`. Pods reach `*.localhost` through a new Service, `kube-system/localhost-ingress` (`clusters/local/localhost-ingress.yaml`). It sits in front of Traefik's pods and answers on 80, 443, 18080 and 18443, and the CoreDNS rewrite now points at it instead of at `traefik`. The same URL therefore works from a pod. Changing `LOCAL_HTTPS_PORT` means changing that Service and `HTTPS_PORT` in `clusters/local/platform.yaml` too (the Makefile comment says so).
- **CNPG.** `platform/cloudnative-pg` (chart 0.29.2, operator 1.30.2), plus `zitadel-db` (namespace `zitadel`, in `platform/zitadel`) and `apps-db` (namespace `databases`, `platform/apps-db`). Each runs one instance on the pinned `ghcr.io/cloudnative-pg/postgresql:18.7-system-trixie`. Storage and memory come from `postBuild.substitute` in `clusters/local/platform.yaml` (`*_DB_STORAGE`, `*_DB_MEMORY`).
- **Tenants list.** It is the `components:` list of the `apps-db` Flux Kustomization in `clusters/local/platform.yaml`. Each entry is a kustomize Component, `clusters/local/tenants/<app>/database`, that adds the CNPG `Database`, the owner's basic-auth Secret, and a JSON patch appending the managed role to `apps-db`'s `spec.managed.roles`. `platform/` still names no app. `wa_owner` is `LOGIN CREATEROLE BYPASSRLS`; `wallet_accountant` is owned by it with `databaseReclaimPolicy: retain`.
- **App namespace.** The `tenant-wallet-accountant` Flux Kustomization (`clusters/local/tenants/wallet-accountant`, dependsOn `apps-db` and `zitadel`) creates the `wallet-accountant` Namespace and the Secrets `wallet-accountant-db-{owner,app,reader}` (key `url`, `sslmode=require`, host `apps-db-rw.databases.svc.cluster.local`), matching the chart README's example. **Ticket 05 must install into this namespace and must not declare the Namespace again.**
- **Zitadel.** Chart 10.5.0, app v4.19.2. It connects through `ZITADEL_DATABASE_POSTGRES_DSN` from CNPG's `zitadel-db-app` Secret. The init Job runs only `init zitadel`, because CNPG already made the database and owner, and a full `init` needs a superuser. `setup` alone fails with no eventstore. Settings: `ExternalDomain: auth.localhost`, `ExternalPort: 18443`, `ExternalSecure: true`, TLS off (it ends at the Gateway through the chart's HTTPRoute), `login.enabled: false`, `LoginV2.Required: false`, `LoginPolicy.AllowRegister: false`. The issuer is `https://auth.localhost:18443`. HelmRelease remediation retries were added because the first install races `zitadel-db` under load.
- **Admin.** Its login name is `admin@zitadel.auth.localhost`, because Zitadel adds the org domain. The password is in `clusters/local/secrets/zitadel/secrets.yaml` (Secret `zitadel-config`, passed as `configSecretName`, so prod can SOPS it). The masterkey is Secret `zitadel-masterkey` in the same throwaway file. Both come in as a Component of the `zitadel` Flux Kustomization, so they land with the namespace. The spec already lists the Zitadel masterkey in 1Password.
- **Machine user.** `platform-setup` (IAM owner). The chart writes its PAT to `zitadel/platform-setup-pat` (key `pat`). The tenant's `zitadel-pat-copy` Job (alpine/k8s 1.35.5, the chart's kubectl image) copies it to `wallet-accountant/zitadel-setup-pat` (key `pat`), the chart's `oidc.zitadelSetup.patSecret`. Its RBAC reads only that one Secret in `zitadel`.
- **local-check.** It now covers: every `kind: Secret` under `clusters/local` carries the THROWAWAY header; CNPG health, instance count and storage; the Database; the role attributes (psql in `apps-db-1`); a sign-in with the owner URL; the issuer from the Mac and from a pod; console authorize redirecting to `/ui/login/login` with no login v2 Deployment; the masterkey Secret ref; the PAT on the admin API and its copy; `allowRegister` not true; and an admin password session via `/v2/sessions`.
- **For ticket 05.** The issuer and browser URLs need `:18443` (`https://wallet.localhost:18443/api`, `WA_OIDC_ISSUER=https://auth.localhost:18443`). The chart builds the `web` redirect URIs as `https://<route.hostname><path>` with no port, so locally they need `oidc.zitadelSetup.web.extraRedirectUris` / `extraPostLogoutRedirectUris` with `:18443`, or a chart change. The pod-side check uses kubectl (Go), not curl: curl resolves `*.localhost` to 127.0.0.1 itself and never asks CoreDNS, while Go's resolver does ask, so the app in a pod reaches Zitadel.
- Caveat as in ticket 03: with other agents' testcontainers and `keystone` sharing the Docker VM, the API server got slow (TLS handshake timeouts), and the first reconcile took about 15 minutes. It converged without manual steps.
