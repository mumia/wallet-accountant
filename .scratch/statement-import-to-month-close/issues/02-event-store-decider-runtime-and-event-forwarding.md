# 02: Event store, Decider runtime and event forwarding

**What to build:** the platform module every aggregate uses. A command loads a fold, decides, appends events and saves the fold in one database transaction. Events are forwarded to deferred handlers in-process, exactly once in effect, with Household isolation applied. This is enabling work, so it is verified by platform integration tests, not by a user-facing endpoint. Spec: `../spec.md` ("Platform module", "Migrations"); ADR-0006, ADR-0011, ADR-0013, ADR-0014, ADR-0015; the spike branch `prototype/spike-eventstore-ogen` is the reference.

**Blocked by:** 01 (Project scaffolding and tooling)

**Status:** resolved

- [ ] The `migrate` run mode runs golang-migrate forward-only as `wa_owner`; `make migrate` runs it against the dev database
- [ ] The first migration creates the three roles (ADR-0014), the event store table, Watermill's offsets table and the processed-events table. The event store has `FORCE ROW LEVEL SECURITY` with the `app.household_id` policy and admits rows with a NULL Household only in instance scope
- [ ] The CloudEvents codec (ADR-0015) encodes and decodes events, carrying `householdid` and `traceparent`
- [ ] The Decider runtime: load fold and version, decide, stamp, encode/decode round-trip, evolve, append, and save if the version is unchanged; it retries on a version conflict
- [ ] A custom Watermill SchemaAdapter forwards events from the event store in-process
- [ ] Handler middleware: a SAVEPOINT per attempt, rolled back before a Nack; processed-events dedup by `(consumer_group, event_id)`; `SET LOCAL ROLE wa_app` plus `set_config` from `householdid` (empty for instance-level events); `RESET ROLE` before ack; the handler continues the event's trace
- [ ] The `worker` and `all` run modes start the forwarder; `make run-worker` works
- [ ] The `rebuild` run mode rebuilds every registered fold from the event store; `make rebuild` works. Later tickets register each new fold
- [ ] A test helper drains every pending event on demand, so deferred effects can be asserted without sleeping
- [ ] Platform integration tests against real PostgreSQL cover the spike's scenarios: gap safety, replay, Nack and shutdown redelivery, and a handler trying to write into another Household

## Comments

Implementation notes (implementer agent):

- **Roles.** A migration cannot create the role it runs as, and creating a `BYPASSRLS` role needs `BYPASSRLS` (or superuser). So the database bootstrap creates `wa_owner LOGIN CREATEROLE BYPASSRLS` and the database it owns (`deploy/dev/postgres-init.sql`, and the test harness the same way). The first migration creates `wa_app` and `wa_event_store_reader` if they are missing (roles are cluster-wide). `migrate` then sets their passwords to the ones in `WA_DATABASE_URL` and `WA_READER_DATABASE_URL`, so each password is written only in its connection string. Ticket 17's self-hosted Compose needs the same bootstrap. **Existing dev volumes still hold the old `wallet_accountant` role:** run `docker compose -f compose.dev.yaml down -v` once, then `make dev-up && make migrate`.
- **Configuration.** New variables: `WA_READER_DATABASE_URL` (needed by `worker`, `all`, `rebuild`) and `WA_OWNER_DATABASE_URL` (needed by `migrate`). They are optional in config parsing; each run mode reports `ErrMissingDatabaseURL` when its URL is missing. `migrate` still needs the OIDC variables because `config.FromEnv` requires them for every mode; ticket 17 may want to relax that for the migrate container.
- **Where things live.** `Decider` and `Envelope` are in `internal/sharedkernel/decider`, because domain packages may import only sharedkernel; `decidertest` provides `Given(t, d, events...).When(cmd).Then(...)/ThenError(...)`. The runtime is `internal/platform/eventstore`: `Store.InTx(ctx, Scope, fn)` (sets `app.household_id`, retries the whole transaction on `ErrVersionConflict`, max 5 attempts), `Tx.SetHousehold` for requests that resolve the User in instance scope first, `Aggregate[S,C,E].Execute`, the `FoldStore[S]` port each context implements, the `Codec[E]` (register with `eventstore.Register[E, T](codec, type)`, `Upcast` for retired schema versions), and `Rebuild`. A unique violation on the stream version constraint is mapped to `ErrVersionConflict`, never leaked. Forwarding is `internal/platform/forwarding`: `Handler{Name, Handle(ctx, pgx.Tx, CloudEvent)}`, where the name is the consumer group; register handlers and rebuild targets in `internal/wiring/registry.go`.
- **Messages.** A Watermill message's payload is the event as a CloudEvent in structured JSON mode (`specversion`, the ADR-0015 attributes, `householdid`/`actorid` omitted when absent, `traceparent`/`tracestate`), so a broker can be added later without another format.
- **Shutdown semantics.** On shutdown the router cancels the subscription context, so pgx usually rolls the subscriber transaction back instead of committing it; the event is then simply handled again. The case the processed-events dedup is for (writes committed without an ack) happens when an attempt outlives Watermill's ack deadline. A dedicated test covers it (`AckDeadline` is configurable), and fails if the dedup is removed. The shutdown test checks the effect happens exactly once across a shutdown and a restart.
- **Drain.** `forwarding.Drain(ctx, reader, groups...)` waits until every group's offset has passed the last event committed when it was called (it polls the offsets table every 10 ms). The HTTP harness now runs the app in `all` mode on a fresh database per `apitest.Start`, connected as `wa_app` and `wa_event_store_reader`, and exposes `app.Drain(t)` over `wiring.ConsumerGroups()`. With no handler registered yet, it returns at once.
- **Tests outside the agreed seams.** Event-store RLS checks at the PostgreSQL level (the spec's "one required exception"), a unit test of the codec, and the platform tests read their own test-only tables (`test_counters`, `test_effects`) to count effects.
- **Checked by hand.** Against a throwaway PostgreSQL started with `deploy/dev/postgres-init.sql`: `migrate` (twice), `rebuild` and `worker` (starts, then stops cleanly on SIGINT). The shared dev Compose stack was not touched.
