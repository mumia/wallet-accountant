# 07: Connections and CSV mapping

**What to build:** a User creates a statement file import Connection for an Account and describes how that bank's CSV is laid out. An invalid mapping is rejected when saved. The mapping can be changed later, and an Account's Connections can be listed. The pure CSV parser (mapping plus bytes to rows or row errors) is built and tested here, ready for imports. Spec: `../spec.md` stories 24–33, "Ingestion: Connection".

**Blocked by:** 06 (Accounts)

**Status:** claimed

- [ ] `POST/GET …/accounts/{account_id}/connections` and `PUT …/connections/{connection_id}/csv-mapping`
- [ ] The mapping covers delimiter, header row, leading lines to skip, date format, decimal separator, thousands separator; each field's column by header name or by position; one signed amount column or separate debit and credit columns; optional Transaction date, Value date, payee and bank transaction ID; and whether the sign means money in or out
- [ ] Saving validates the whole mapping: missing required field, unknown date format, or the same column used twice are rejected with problem+json
- [ ] The mapping has a version that changes on every save (the first import's preview relies on it)
- [ ] Pure parser: mapping plus file bytes to rows or a list of row numbers and reasons; Transaction date defaults to Booking date

## Comments

Implementation notes (implementer agent):

- **Where things live.** Connection Decider in `internal/ingestion/domain/connection.go` (commands `CreateConnection`, optionally with a mapping, and `SaveCSVMapping`; events `io.walletaccountant.ingestion.connection.created.v1` and `…connection.csvmappingsaved.v1`). The mapping value object and its whole-mapping validation are in `domain/csvmapping.go`; the pure parser `domain.ParseStatementFile(mapping, bytes)` is in `domain/statementfile.go`. Service `ingestionapp.Connections` (`Create`, `List`, `SaveCSVMapping`) in `internal/ingestion/app/connections.go`, with its own `HouseholdScope` port and an `Accounts` port (`AccountExists`), which `ledgerapp.Accounts` now implements. Fold store and reader in `internal/ingestion/adapters/postgres/connections.go`; HTTP operations on `ingestionhttp.ConnectionHandler` (`internal/ingestion/adapters/http/connections.go`), embedded in `wiring.apiHandler`. `wiring.Contexts` gained `Connections`; the Connection aggregate is a rebuild target. Migration `000007_connections` (the mapping is a `jsonb` column).
- **Contract.** `POST/GET …/accounts/{account_id}/connections`, `PUT …/connections/{connection_id}/csv-mapping` (200 with the Connection). `kind` is `x-extensible-enum` `STATEMENT_FILE_IMPORT`; `BANK_FEED` or anything else gets 422 `/problems/invalid-connection`. POST takes an optional `csv_mapping`. The `CsvMapping` schema has every property optional on purpose, so a missing field reaches the domain and is reported together with every other problem as 422 `/problems/invalid-csv-mapping`, whose `detail` lists them all. `amount_layout` is `SIGNED|DEBIT_CREDIT`; `positive_amount_means` is `MONEY_IN|MONEY_OUT` and is required for SIGNED and refused for DEBIT_CREDIT (debits are always money out, credits money in, whatever sign the bank writes). Date formats are the strings `YYYY-MM-DD`, `YYYY/MM/DD`, `YYYYMMDD`, `DD/MM/YYYY`, `DD-MM-YYYY`, `DD.MM.YYYY`, `MM/DD/YYYY`, `MM-DD-YYYY`, `DD/MM/YY`, `MM/DD/YY`, listed in the description, not as an enum, because vacuum's Zalando rules want UPPER_SNAKE_CASE enum values. Columns are `{header}` or `{position}` (from 1); headers match ignoring case and surrounding spaces. A Connection of an Account not in the path (another Account, another Household) answers 404.
- **Mapping version.** `csv_mapping_version` counts saves (1, 2, 3, …), changes on every save even of an identical mapping, and is absent while there is no mapping. Ticket 08's `preview_id` can hash it.
- **Parser (for ticket 08).** `ParseStatementFile` returns `[]StatementRow` (line number, Booking/Transaction/Value dates, description, payee, bank transaction ID, signed `sharedkernel.Decimal` amount with positive = money in) or a `*domain.RowsError` (`errors.Is(err, domain.ErrUnreadableRows)`) listing every bad line with its reason; an invalid mapping comes back as the mapping's own error. Line numbers are physical lines, counting skipped lines and the header row. A UTF-8 BOM is dropped. Blank Transaction date falls back to the Booking date; blank Value date stays zero. An empty file gives no rows and no error, so ticket 08 decides whether that's refused. The parser doesn't round to the Account currency's decimal places: ticket 08 should refuse rows with more decimals than the currency allows.
- **Shared kernel.** Added `sharedkernel.Decimal` (an alias of `shopspring/decimal.Decimal`) and `ParseDecimal`, because depguard lets `domain` import only the standard library and the shared kernel.
- **Harness.** Added `App.Put` in `internal/apitest/put.go` (its own file, to avoid clashing with ticket 05).
- **Tests.** Decider given/when/then for creation (with and without a mapping, bank feed, unknown kind, twice), versioning, and every validation rule, plus one test that a mapping with three problems reports all three. Parser tests for signed vs debit/credit, header vs positional, inverted sign, decimal and thousands separators, every date format, skipped leading lines, every optional field, quoted delimiters, and row errors (bad dates, bad or missing amounts, short rows, debit and credit both set or both blank, a header without a mapped column, invalid CSV). HTTP: create, list, save every kind of mapping, versioning, every refusal (and nothing changed after them), rebuild, Idempotency-Key replay, unknown Account 404, and 404 for another Household (in its own Household and through the caller's). `databasetest.AssertHouseholdIsolation` for `connections`. Mutation checked by hand: dropping the Connection's Account check fails the "saving through another Account" test.
- **Consistency map.** The Save CSV mapping row now says the mapping is validated as a whole and saved with a new mapping version, also when a Connection is created with its mapping. Nothing is deferred.
