# 15: Month status and Month close

**What to build:** a User sees each Booking month's status for an Account and closes it by entering the Statement balance. The close is refused, listing every reason at once, while anything is pending or an undecided Suspected duplicate, anything is Uncategorised, a relevant Balance check is waiting or failed, or the computed balance differs from the Statement balance. There is no balancing entry. Spec: `../spec.md` stories 53–61, 64, "Ledger: Account", "Cross-context calls: Month close"; ADR-0018.

**Blocked by:** 10 (Recategorise, reverse Transactions and Discard pending Imported transactions), 12 (Suspected duplicates, Keep, and the waiting Balance check)

**Status:** resolved

- [ ] `GET …/accounts/{account_id}/months/{booking_month}` returns open or closed, Statement balance, computed balance, pending count, undecided Suspected duplicate count, Uncategorised count and flagged
- [ ] `POST …/accounts/{account_id}/months/{booking_month}/close` with the Statement balance; months are decided by Booking date
- [ ] Ledger reads unresolved Imported transactions (pending and Suspected duplicate) and Balance check states through an Ingestion `app` port
- [ ] Close conditions, decided by the Account Decider: Uncategorised count zero; computed closing balance (Opening balance plus every month up to this one) equals the Statement balance exactly; no unresolved Imported transactions for the Account and month; no Statement import with rows in or before the month whose check is waiting or failed; month not already closed
- [ ] A refusal returns every failed condition together, with both amounts and the difference for a balance mismatch
- [ ] No endpoint records a balancing entry
- [ ] Decider tests: each condition singly and together
- [ ] HTTP tests: every rejection reason singly and together; a successful close; closing an already-closed month refused; another Household gets 404
- [ ] Consistency map row for Close month matches the code

## Comments

Implementation notes (implementer agent):

- **Paths.** Under the Account (within Zalando's three sub-resource levels): `GET /households/{h}/accounts/{a}/months/{booking_month}` (`getAccountMonth`, 200 `AccountMonth`) and `POST …/months/{booking_month}/close` (`closeAccountMonth`, body `MonthClosing {statement_balance: Money}`, 200 `AccountMonth`). `AccountMonth`: `account_id`, `booking_month`, `state` (`OPEN`/`CLOSED`), `statement_balance` and `closed_at` once closed, `computed_balance` (absent while the Account awaits its first import), `pending`, `suspected_duplicates`, `uncategorised`, `flagged` (always false until ticket 16). New tag `Months`, path parameter `BookingMonthPath`.
- **Problems.** 422 `/problems/month-close-refused` (`MonthCloseProblem`): `reasons` lists every failed condition (`PENDING`, `SUSPECTED_DUPLICATES`, `UNCATEGORISED`, `BALANCE_CHECK_NOT_PASSED`, `BALANCE_MISMATCH`) with its details beside it (`pending`, `suspected_duplicates`, `uncategorised`, `unchecked_statement_imports` [{`statement_import_id`, `balance_check` WAITING/FAILED}], `computed_balance`, `statement_balance`, `difference` = Statement minus computed). 409 `/problems/month-already-closed` and 409 `/problems/account-awaiting-first-statement-import`; 422 `/problems/invalid-month-close` for a Statement balance in another currency, with too many decimal places, or a month before the start date month; 400 for a malformed month; 404 for an unknown or another Household's Account. "Already closed" is a separate 409 (checked first), not one of the listed reasons: it is a state conflict, and listing it with the others would invite "fixing" a month that can't be closed again anyway.
- **Ledger.** Account Decider: `CloseMonth{Month, StatementBalance, Imports domain.MonthImports}` → `io.walletaccountant.ledger.account.monthclosed.v1` (`MonthClosed{Month, StatementBalance}`; closed at/by come from the event's envelope time (to the microsecond) and actor). Refusals as `*domain.MonthCloseRefusedError` (`ErrMonthCloseRefused`) with every failed condition. `AccountState.Closed map[month]MonthClose{StatementBalance, ClosedAt, ClosedBy, Flagged}` and `ClosingBalance(month)` (sum of every month ≤ month, Opening balance included). Fold schema version 4. `ledgerapp.Months` (`internal/ledger/app/months.go`) with `Status` and `Close`; the Ledger `Ingestion` port gains `MonthImports` (status) and `MonthImportsForClose` (takes ticket 11's per-Account import advisory lock first, so a concurrent upload or waiting check is seen whole). Adapters in `internal/wiring/ledgerport.go`.
- **Ingestion.** `ImportedTransactions.MonthImports` / `MonthImportsForClose`, reader `StatementImportReader.MonthImports`: pending and `suspected_duplicate` rows by Booking date in the month (Discarded don't count), and non-voided imports with `balance_check IN ('waiting','failed')` having any row (any state) booked before the month's end, ordered by ID. Mutations dropping `voided_at IS NULL` or the "in or before" condition fail the HTTP tests.
- **Migration** `000015_month_close`: `account_months.statement_balance`, `closed_at`, `closed_by`, `flagged` (open while `statement_balance` is NULL). No new table, so no new RLS test. A closed month with no Transactions is saved as a row with net change 0.
- **Tests.** Decider (`internal/ledger/domain/month_close_test.go`): closing (incl. an empty month), the fold, each condition singly (Uncategorised, mismatch with amounts and difference, pending, Suspected duplicate, waiting check, failed check), all together, and refusals (not added, awaiting, before start, too many decimals, already closed; another month still closes). HTTP (`internal/ingestion/adapters/http/month_close_integration_test.go`, beside the import fixtures): month status following Accept, recategorise and reverse (Uncategorised and pending counts, computed balance — the carry-over from 09/10), awaiting account, successful close (nothing booked, balance and transaction list unchanged), already closed 409, pending / Uncategorised / mismatch singly, waiting check singly (then passes and closes), failed check singly (then void and close), voided import with a waiting check ignored, an import with rows only after the month ignored, everything together, invalid currency/decimals/month, 400 and 404, another Household 404 (both paths), Idempotency-Key replay, rebuild.
- **Not singly at the HTTP seam.** An undecided Suspected duplicate always leaves its own import's check waiting, so over HTTP `SUSPECTED_DUPLICATES` comes with `BALANCE_CHECK_NOT_PASSED`; it is tested singly at the Decider seam.
- **For ticket 16.** `MonthClose.Flagged` and `account_months.flagged` exist but nothing sets them; set it in `evolveAccount` for `TransactionBooked`, `ReversalBooked`, `TransactionRecategorised` and `OpeningBalanceReversed` when `s.Closed[month]` exists (and `GET` will show it).
- **Consistency map.** Close month row rewritten to what the code does.
