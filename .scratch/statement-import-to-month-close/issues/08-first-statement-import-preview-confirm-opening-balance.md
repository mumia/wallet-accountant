# 08: First Statement import: preview, confirm and Opening balance

**What to build:** a User uploads an Account's first statement file with its Export balance typed twice, previews the Opening balance it would produce, and confirms. The import is recorded, every row becomes a pending Imported transaction, and the Opening balance Transaction is recorded on the start date. The Account now shows its balance, and its single-entry transaction list shows the Opening balance. Spec: `../spec.md` stories 17, 17a, 21–23, 34–37, 41–42, 43a, 43g, 43h, 44, "Ingestion: Statement import", "Opening balance"; ADR-0001, ADR-0011, ADR-0018.

**Blocked by:** 07 (Connections and CSV mapping)

**Status:** resolved

- [ ] `POST …/connections/{connection_id}/statement-imports/previews` (multipart: file, `export_balance`, `export_balance_confirmation`) refuses mismatched entries and otherwise returns `preview_id`, the Opening balance on the start date, the row count, rows ignored before the start date and the rows' total. It records nothing
- [ ] `preview_id` is a hash of Account ID, file hash, Export balance and mapping version, so the server keeps no state
- [ ] `POST …/statement-imports` with `preview_id` recomputes it and refuses a different file, Export balance or mapping version; refuses if the Account already got its Opening balance; refuses a first import without `preview_id`
- [ ] Confirm records the Statement import, its Imported transactions (pending) and the Opening balance Transaction in one database transaction, through a Ledger `app` port. The Account stops awaiting its first import
- [ ] Ledger Transaction Decider: Postings sum to zero per currency, each names one Account or one Category; its fold saves one lookup row per Account Posting in the same database transaction
- [ ] Rows booked before the start date are ignored and counted; a file with any unreadable row is rejected whole with row numbers and reasons; the same file again is refused with a pointer to the earlier import
- [ ] `GET …/accounts/{account_id}` shows the balance; `GET …/accounts/{account_id}/transactions?booking_month=YYYY-MM` returns the single-entry list (signed amount, Booking date, Transaction date, description, Category) with cursor paging, read inside the request transaction
- [ ] `GET …/statement-imports` lists a Connection's imports; `GET …/accounts/{account_id}/imported-transactions?state=pending&booking_month=YYYY-MM` lists rows waiting for review
- [ ] HTTP tests: preview records nothing, every confirm refusal, Opening balance with rows before the start date ignored, duplicate file, row-level rejection, Idempotency-Key replay of the upload, transaction list paging and month filter; another Household gets 404
- [ ] Row-level security test for every table this ticket adds; new folds registered for rebuild
- [ ] Consistency map rows for Preview first Statement import and Upload Statement import (first import) match the code

## Comments

Implementation notes (implementer agent):

- **Paths.** Zalando's "≤ 3 sub-resource levels" rule (vacuum, fail on warn) refuses `/households/{h}/accounts/{a}/connections/{c}/statement-imports/previews`, so Statement imports hang off the Household: `POST /households/{h}/connections/{c}/statement-imports/previews`, `POST/GET /households/{h}/connections/{c}/statement-imports`. A Connection is found by its ID within the Household. Ticket 14's `…/statement-imports/{id}/void` fits the same prefix. `GET …/accounts/{a}/transactions` and `GET …/accounts/{a}/imported-transactions` are under the Account as the spec says.
- **Where things live.** Ledger: Transaction Decider `internal/ledger/domain/transaction.go` (`RecordTransaction` → `io.walletaccountant.ledger.transaction.recorded.v1`; Postings sum to zero per currency, each names exactly one Account or one Category, amounts fit the currency's decimal places; `AccountLines()` gives one line per Account Posting with the single Category on the other side). Account Decider gains `RecordOpeningBalance` → `…ledger.account.openingbalancerecorded.v1` (refused unless awaiting its first import), `Months` (net change per Booking month, `YYYY-MM`), `Balance()`, `HasBalance()`; fold schema version 2. `ledgerapp.Transactions` (`RecordOpeningBalance` port method, `List`) in `internal/ledger/app/transactions.go`; `ledgerapp.Accounts.AccountForImport`. Ingestion: `domain.ReadStatement` (parse with the currency's decimal places, ignore and count rows before the start date, total), `PreviewID`, `FileHash`, `CheckExportBalance` in `domain/statement.go`; Statement import and Imported transaction Deciders in `domain/statementimport.go`; `ingestionapp.StatementImports` (`Preview`, `Upload`, `List`) and `ingestionapp.ImportedTransactions` (`List`). Ingestion declares its own `Ledger` port; `internal/wiring/ledgerport.go` adapts the Ledger services to it, so neither context imports the other. Migration `000008_statement_imports_and_transactions` (tables `statement_imports`, `imported_transactions`, `ledger_transactions`, `account_postings` (the lookup rows), `account_months`, and `accounts.opening_balance_transaction_id`). Transaction, Statement import and Imported transaction aggregates are rebuild targets.
- **preview_id.** SHA-256 of Account ID, Connection ID (added to the spec's list: two Connections of one Account can share a mapping version), file hash, Export balance by value (`100.5` = `100.50`) and mapping version. Confirm recomputes it; any difference is 422 `/problems/preview-mismatch`.
- **Problem types.** 422: `/problems/export-balance-mismatch`, `/problems/invalid-export-balance`, `/problems/unreadable-statement-file` (with `rows: [{line, reason}]`), `/problems/empty-statement-file`, `/problems/csv-mapping-required`, `/problems/preview-required`, `/problems/preview-mismatch`, `/problems/later-statement-imports-not-supported`, `/problems/statement-file-too-large` (16 MiB). 409: `/problems/duplicate-statement-import` (with `statement_import_id` of the earlier import), `/problems/opening-balance-already-recorded`. A malformed `export_balance` (e.g. `2.500,00`) fails the contract's pattern: 400.
- **Later imports (ticket 11).** An Account that has its Opening balance gets 409 for any upload with `preview_id` and 422 `later-statement-imports-not-supported` without one; the Statement import Decider refuses `First: false` with `ErrLaterImportsNotSupported`. Ticket 11 replaces both. `balance_check` is an `x-extensible-enum` with only `PASSED` so far; Imported transaction `state` only `PENDING`.
- **Carry-over from 06 (decimal places on the wire).** `Money.amount` now has `x-ogen-type: …/internal/platform/httpapi/amount.Amount`, a type that writes `StringFixed(places)` of its currency, so EUR 100 goes out as `100.00`, JPY as `1500`, ETH with 18 places. Build it with `amount.Of(value, currencyCode)`. Unit-tested in the package and checked on the raw JSON in the preview HTTP test (a mutation back to `String()` fails it).
- **Carry-over from 07 (decimals and empty files).** `ReadStatement` refuses, as a row error, any amount whose value has more decimal places than the Account currency (judged by value: `1,500` is fine in EUR, `1,505` isn't), reported with every other bad line. A file with no rows at all (empty, or only a header) is refused with 422 `/problems/empty-statement-file`: there's nothing to import, it's most likely a wrong export, and recording it would lock its hash. A file whose rows are all before the start date is accepted (0 rows, Opening balance = Export balance).
- **Carry-over from 04 (multipart idempotency).** The middleware compares a `multipart/form-data` body by its parts (name, file name, part content type, content; order-insensitive) instead of its bytes. `apitest.App.PostForm` builds a fresh form, with a new random boundary, on every call; the replay test fails if the comparison is reverted to raw bytes (checked by hand).
- **Concurrency.** Two confirms of one first import: the Account's version check makes the second retry and find the Opening balance (409). Two uploads of one file: a unique index on (household, connection, file hash) turns the second insert into a version conflict, so its retry reports the duplicate. Row and Opening balance IDs are generated once per request and reused across retries.
- **Tests.** Decider given/when/then: Transaction (balanced, zero Opening balance, unbalanced per currency, posting targets, too few postings, no Booking date, decimal places, twice, Account lines), Account Opening balance (event, fold balance and month, refusals), Statement import and Imported transaction (record, refusals, fold), statement reading (start date, all before it, decimal places in EUR/BHD/JPY, empty files, Export balance), preview ID. HTTP: preview records nothing (with raw JSON decimals), mismatched/invalid Export balances, confirm with rows before the start date ignored (balance, transaction list, pending rows, month filter, import list), every confirm refusal (no preview_id, other file, other Export balance, mapping changed, stale preview, later import, no mapping) with nothing recorded, duplicate file (upload and preview), row-level rejection (preview and upload), empty file, Idempotency-Key replay with a rebuilt form and a mismatch, paging and filters, rebuild, and 404 for another Household (through hers and his own). `AssertHouseholdIsolation` for all five new tables.
- **Not fully covered yet.** Only the Opening balance can be booked in this ticket, so an Account's transaction list never has a second line: its month filter, `limit` and invalid cursor are tested, but a multi-page walk of the transaction list is tested only for Imported transactions (same keyset mechanism). Ticket 09 (Accept) should add a multi-page transaction-list test.
- **Consistency map.** Upload Statement import and Preview first Statement import rows now spell out what the first import reads and records through the Ledger port; the rest of the Upload row (Suspected duplicates, Balance check, Notification) is for tickets 11–13.
