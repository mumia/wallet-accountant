# Consistency map

What each command changes immediately (in the same database transaction) and what follows later through domain events. The rule behind it is ADR-0013: immediate if a User would notice a delay or an inconsistency, deferred otherwise.

Every spec that adds or changes a command adds or updates its row here. Code review checks the code against this table.

| Command | Context | Immediate (same transaction) | Deferred (via events) |
|---|---|---|---|
| Issue bootstrap Invitation | Households | Bootstrap Invitation issued, or reissued with a new code if still unredeemed; its code lookup row updated | — |
| Redeem Invitation | Households | Invitation redeemed; User registered with the Invitation's role and its identity lookup row saved | — |
| Create Household | Households → Ledger | Household created; creator added as member, with the User's membership index row; the three Internal Categories (Opening balance, Household transfer, Uncategorised) created | — |
| Create Category | Ledger | Household's Category tree locked; parent and sibling names read and checked; Category created | — |
| Add Account | Ledger | Account created, awaiting its first Statement import | — |
| Save CSV mapping | Ingestion | Connection's mapping validated as a whole and saved with a new mapping version (also when a Connection is created with its mapping) | — |
| Upload Statement import | Ingestion → Ledger | Connection's mapping, the Account (through the Ledger port) and earlier imports of the same file read and checked; Statement import recorded with its Export balance; new Imported transactions recorded as pending or Suspected duplicate; certain repeats skipped; Balance check run, or left waiting for Suspected duplicates. First import only (its `preview_id` recomputed and checked): one pending Imported transaction per row on or after the start date, then through the Ledger port the Account's Opening balance recorded (refused if it already has one), so it stops awaiting its first Statement import and its balance is set, and the Opening balance Transaction recorded on the start date with its Account Posting lookup row (the Account transaction list). Later imports only (no `preview_id`, Export balance given once): the Account's Statement imports locked; its Opening balance and every non-Discarded Imported transaction (pending, Accepted, kept) read from Ingestion's own folds, never Ledger Transactions; rows matching an earlier one by bank transaction ID, Booking date and amount skipped and counted; rows that only look like an earlier non-Discarded one (same bank transaction ID with another Booking date or amount; or, without a bank transaction ID, the same Booking date, amount and normalised description), never compared within the file, imported as Suspected duplicates recording the earlier Imported transaction they resemble, and counted on the Statement import; with no Suspected duplicates the Balance check is run on the rest, and a failed check refuses the whole import, recording nothing, otherwise the Statement import is recorded with its check passed and its new rows pending; with Suspected duplicates the Statement import is recorded with its check waiting, whatever the check would say now | Notification to the Household when Suspected duplicates were found (from `statementimport.recorded`, which carries the Statement import and its Suspected duplicate count) |
| Keep or Discard Imported transaction | Ingestion | Keep: a Suspected duplicate moved to pending (refused for any other state). Discard: a pending row or a Suspected duplicate moved to Discarded (refused when Accepted or already Discarded; Discarded is final, and later Balance checks, certain-repeat and Suspected-duplicate matching leave it out). Deciding a Suspected duplicate first locks its Account's Statement imports; then, if none of its Statement import's Suspected duplicates is left, the waiting Balance check is run on the Account's Opening balance and its non-Discarded Imported transactions from that import and the ones recorded before it, and recorded as passed or failed (a failed check keeps the import; it is fixed by voiding) | — |
| Preview first Statement import | Ingestion ← Ledger | Nothing recorded: the Connection's mapping, the Account (through the Ledger port) and earlier imports of the same file are only read | — |
| Void Statement import | Ingestion → Ledger | Statement import voided; its Imported transactions Discarded; file hash released. First import only: Opening balance Transaction reversed, Account back to awaiting its first Statement import | — |
| Accept imported transaction | Ingestion → Ledger | Imported transaction marked Accepted (refused unless pending) and linked to its Transaction; through the Ledger port the chosen Category read and checked (none, or Uncategorised, books to Uncategorised; any other Internal Category refused), the Account's balance and Uncategorised count for the Booking month updated, and the Ledger Transaction recorded with the row's exact amount, dates, description and payee, linked to the Imported transaction, with its Account Posting lookup row (Account transaction list). Closed-month flags come with Month close | Category totals, Budget actuals, Forecasts, Match suggestions |
| Set Transaction Category | Ledger | Transaction's Category on the non-Account side changed with Accept's Category rules (Uncategorised allowed, any other Internal Category refused), its amount untouched; refused for a reversed Transaction, a reversal and the Opening balance Transaction; Account's Uncategorised count for the Booking month moved in or out; its Account Posting lookup row updated (Account transaction list). The same Category again records nothing. Closed-month flags come with Month close | Category totals, Budget actuals |
| Reverse Transaction | Ledger → Ingestion | Transaction marked reversed (refused for the Opening balance Transaction, a reversal, or one already reversed); reversing Transaction recorded with the opposite Postings, the same dates, description and payee, linked both ways; every touched Account's balance moved back in the Booking month and the original taken out of its Uncategorised count (neither counts); both Account Posting lookup rows in the Account transaction list; through the Ingestion port, the linked Imported transaction back to pending and unlinked, so it can be Accepted again or Discarded. Closed-month flags come with Month close | Category totals, Budget actuals |
| Close month | Ledger ← Ingestion | Unresolved Imported transactions and Balance checks checked through the Ingestion port; Account month marked closed with its Statement balance | — |
| Rename or move Category | Ledger | Household's Category tree locked; new parent and sibling names read and checked; Category renamed and/or moved | — |
